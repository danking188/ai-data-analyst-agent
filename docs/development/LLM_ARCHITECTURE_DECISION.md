# ADR-002：证据优先的大模型接入架构

状态：已采用
日期：2026-07-13
关联计划：[`LLM_EXTENSION_PLAN.md`](LLM_EXTENSION_PLAN.md)

## 1. 背景

DataTrace 已经具备真实数据上传、质量扫描、清洗、统计分析、模型训练、Artifact、Claim 和
报告导出能力。大模型接入的价值是让用户通过自然语言完成意图表达、分析规划和结果理解，
而不是替代现有确定性计算。

如果让大模型直接生成指标、执行任意代码或绕过领域服务，会破坏项目现有的权限隔离、数据版本、
证据链和可复现性。因此需要在实现对话功能之前冻结架构边界。

## 2. 决策

### 2.1 Provider

- 后端定义供应商无关的 `LLMProvider` Protocol。
- 首个真实适配器使用 OpenAI-compatible Chat Completions HTTP 协议。
- 业务服务不直接依赖供应商 SDK、模型名称或响应原始结构。
- 使用 `FakeLLMProvider` 完成无网络单元测试、集成测试和离线评估。
- 所有业务输出使用 Pydantic 严格结构化 Schema，拒绝额外字段和非 JSON 文本。

### 2.2 数据与证据

- LLM 只接收完成当前任务所需的最小上下文。
- 默认上下文是 Schema、聚合画像、Artifact 摘要、已验证 Claim 和限制说明。
- 原始敏感值、完整数据文件、凭证、Cookie、内部路径和签名地址不得进入 Prompt。
- 所有数字结论必须引用当前项目可见的 Artifact/Claim，并由确定性校验器验证。
- LLM 不得修改 Claim 的验证状态，也不得生成统计或模型指标作为事实源。

### 2.3 工具与执行

- Agent 只能调用版本化白名单工具，工具内部必须调用现有 Service 层。
- 不开放任意 Python、Shell、SQL、网络请求或文件路径工具。
- 读取工具可直接执行；创建 Run、执行清洗、激活版本和导出等操作需要用户确认。
- 重试必须保持幂等，确认记录和工具调用必须可审计。

### 2.4 运行方式

- 长模型调用由数据库队列 Worker 执行，不占用 API 请求事务。
- Assistant 使用独立 `assistant_turn` Job；等待确认时结束当前 Job，由确认请求创建续跑 Job。
- 每 Turn 设置模型调用数、工具调用数、输入输出 Token、超时和用户日预算。
- `LLM_ENABLED=false` 是完整降级路径，关闭后现有核心功能不受影响。

### 2.5 安全与可运维性

- API Key 只从运行环境读取，不写入数据库、Job、Artifact、日志或前端。
- 上传文件和数据单元格中的文本一律视为不可信数据，不能改变系统指令或工具权限。
- Provider 的认证、限流、服务端错误、超时、断网和非法响应映射为稳定安全错误码。
- 记录 Provider、模型、Prompt 版本、Token、延迟和资源引用，不记录完整敏感请求/响应。
- 生产采用功能开关灰度启用，Provider 故障不能让整个应用 readiness 失败。

## 3. 被否决方案

### 前端直连模型 API

否决原因：会暴露密钥，无法统一执行权限、预算、审计、证据校验和数据脱敏。

### 让模型生成并执行任意 Python/SQL

否决原因：当前沙箱和项目权限模型不支持把不可信代码作为生产分析路径；难以保证资源限制、
幂等、证据和可复现性。

### 只保存模型最终文本

否决原因：无法追踪 Prompt 版本、模型调用、工具调用、用户确认和证据引用，也无法进行可靠评估。

### 把整个数据集发送给模型

否决原因：成本不可控，可能违反数据最小化和隐私要求，并且不能提高真实统计计算的可靠性。

## 4. 影响

正向影响：

- 可以替换模型供应商而不改动业务服务；
- 现有 Artifact/Claim 成为自然语言回答的可靠事实源；
- 可通过 Fake Provider 稳定测试，不依赖外部网络；
- 大模型关闭或故障时系统仍可完成真实分析。

代价：

- 需要新增会话、模型运行、工具调用和反馈持久化；
- 每种工具和回答都要维护结构化 Schema 与版本；
- 上线前必须建立离线评估集和持续成本监控；
- 相比直接聊天接口，首个可用版本实现周期更长。

## 5. 复审条件

出现以下情况时新增 ADR，不直接改写本决策历史：

- 引入非 OpenAI-compatible Provider；
- 允许本地模型在受控推理服务运行；
- 引入可执行代码沙箱、向量数据库或多 Agent；
- 外部模型数据处理条款要求改变默认数据边界；
- 产品需要实时 Token 流式传输替代现有 Job 轮询。
